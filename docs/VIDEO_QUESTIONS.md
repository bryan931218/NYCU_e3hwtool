# 影片提問維護

## 取材流程

音訊取得及轉錄與畫面取樣並行執行，每次最多三個取材工作。提問當下優先擷取原始影格，失敗才使用預覽縮圖；前後畫面維持預覽取樣。字幕不是必要條件。

成功音訊片段在單一程序內快取 15 分鐘，最多 24 段；轉錄以音訊內容雜湊、模型、科目與影片名稱為鍵，快取 30 分鐘，最多 64 筆。不快取失敗或空白轉錄。問題內容不注入轉錄提示，避免問題引導出不存在的語音。不同問題仍會分別生成回答。

YouTube 串流可能因上游限制回傳 403。最低 yt-dlp 版本為 2026.8.19，修正舊版 android_vr 的相容性問題。部署需重新安裝 requirements，不能只替換 Python 原始碼。Node.js 22 已包含於 nixpacks 設定。取材期間不再臨時下載及編譯 token provider；有預先建立的 provider 才會使用。

缺少語音時，介面會標示本次只依畫面回答；模型不能把縮圖看不清的公式或沒取得的語音當成確定事實。程序內快取不跨 Gunicorn worker 或重啟共享。

## 可選原片備援

設定 `E3_VIDEO_MEDIA_ROOT` 指向伺服器可讀的原始影片根目錄。目錄結構須為 `<根目錄>/<科目>/<網站影片完整名稱>.mp4`，也支援 mkv、webm、mov。僅精確名稱符合且實際路徑位於根目錄內才會使用，不會用相近檔名猜測。

本機可設定為 `E:\影片`；Railway 必須另外掛載原始影片，不會自動讀到個人電腦的磁碟。原片不可提交 Git。原片提供高清畫面與單聲道音訊，失敗時仍可回退 YouTube。

## 診斷

只測 YouTube 畫面與音訊，不呼叫付費 AI：

```sh
python backend/tools/check_video_question.py 0RqGBxykqfk --seconds 120
```

加上 `--question "這段在說明什麼？"` 才會實際呼叫語音轉錄與回答 API，使用暫存資料庫，不會修改正式觀看紀錄。網路/IP 限制仍須在實際部署環境驗證，本機成功不代表 Railway 一定成功。
